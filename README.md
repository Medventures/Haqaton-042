# MedRep — AI-ассистент для заполнения бланка консультации

**Команда:** MedRep · **Статус:** демонстрационный прототип, 30 сентября 2026 года.

## Проблема

Врач одновременно разговаривает с пациентом, изучает прошлые записи и заполняет медицинский бланк. MedRep сокращает повторный ввод: переносит подтверждённые сведения из разговора в черновик, который врач проверяет и исправляет.

## Решение

Три рабочие области на одном экране:

1. **История слева:** прошлые консультации и анализы, поиск по «ОАК» и «общий анализ крови», прошлые рекомендации с указанием их исторического контекста.
2. **Разговор в центре:** расшифровка, время реплик, редактирование текста и ролей врача/пациента.
3. **Бланк справа:** редактируемый черновик по предоставленному шаблону «ЖДА ВОП-1.docx», скачивание Word и подтверждение отправки в тестовую МИС.

Путь обработки: аудио → WhisperX → расшифровка → серверный анализ OpenAI → 13 разделов бланка → проверка врачом → DOCX или тестовая МИС. Для питча используется заранее сохранённая расшифровка: повторное распознавание не требуется.

LLM выбирает цитаты и их разделы; сервер проверяет связь с исходной репликой и роль говорящего. Неподтверждённые сведения не добавляются. Ручные правки имеют приоритет. Исторические назначения не становятся назначениями сегодняшнего приёма автоматически.

**Стек:** React 19, TypeScript, Vite, FastAPI / Python 3.12, WhisperX, OpenAI Responses API, PostgreSQL 17, Nginx, Docker Compose.

## Демо

Основной адрес контейнерного стенда: **http://127.0.0.1:5174/**. Это локальное приложение, публичного размещения пока нет.

- **Демо** открывается по умолчанию и загружает подготовленную расшифровку из PostgreSQL, если она импортирована. Слева показаны три явно помеченные вымышленные прошлые записи.
- **Платформа** открывает пустой приём: http://127.0.0.1:5174/?mode=platform.
- Переключение режимов сохраняет их черновики отдельно в памяти текущей вкладки. Перезагрузка страницы их сбрасывает.
- **Пример приёма** запускает встроенный учебный разговор без микрофона, WhisperX и OpenAI. Он доступен и без импортированной записи; для запуска самого контейнерного стенда серверные секреты всё равно нужны.

### Сценарий показа

1. Откройте «Демо» на подготовленном стенде. Дождитесь «OpenAI: черновик готов»; на проверенной конфигурации разбор занимал около 4 секунд, время зависит от внешнего API.
2. Введите слева **ОАК** или **общий анализ крови**, покажите прошлый анализ и рекомендацию о контроле.
3. Покажите расшифровку и бланк справа. Исправьте реплику или поле; проверьте сохранение ручной правки.
4. Отметьте **«Бланк проверен, можно выдать пациенту»**, затем **«Скачать Word»**.
5. Внизу бланка подтвердите использование только тестовых данных и нажмите **«Подтвердить и отправить в МИС»**. Появится номер документа. **«Прочитать бланк из базы МИС»** возвращает сохранённый результат.

**Ограничение текущего стенда:** загрузка модели в контейнере транскрибации завершается ошибкой. Новое распознавание в контейнерах пока не подтверждено; его исправление отложено. Сохранённая расшифровка, OpenAI, Word и тестовая МИС проверены отдельно. На питче используйте сохранённое демо.

## Запуск

### Docker Compose — основной вариант

Требуются Docker Desktop / Docker Engine с Compose v2 и интернет для загрузки зависимостей, моделей и обращения к OpenAI. Node.js и Python на хосте для этого варианта не нужны.

```bash
git clone https://github.com/Medventures/Haqaton-042.git
cd Haqaton-042
```

Скопируйте `.env.example` в `.env`: `Copy-Item .env.example .env` в PowerShell или `cp .env.example .env` в Bash. Замените значения-заглушки собственными секретами:

| Переменная | Назначение |
| --- | --- |
| `POSTGRES_PASSWORD` | Пароль тестовой PostgreSQL; используйте URL-безопасное случайное значение, так как он включается в строку подключения. |
| `TRANSCRIPTION_API_KEY` | Независимый ключ сервиса распознавания, минимум 24 символа. |
| `MIS_API_KEY` | Отдельный случайный ключ backend → тестовая МИС, минимум 24 символа. Это не ключ OpenAI. |
| `OPENAI_API_KEY` | Ключ серверного анализа текста; без него доступен предварительный разбор локальными правилами. |
| `OPENAI_MODEL` | По умолчанию `gpt-4.1-mini`. |
| `HF_TOKEN` | Необязательный токен для диаризации; нужны права доступа к используемым моделям. |
| `WHISPER_MODEL` | По умолчанию `large-v3`; имя модели или доступный контейнеру путь. |
| `MODEL_CACHE_DIR` | Каталог моделей на хосте, по умолчанию `./model-cache`; монтируется в `/models`. |

```bash
docker compose up -d --build
docker compose ps
```

Compose содержит **5 сервисов**:

| Сервис | Адрес на хосте |
| --- | --- |
| `frontend` — Nginx / React | http://127.0.0.1:5174/ |
| `backend` — FastAPI | http://127.0.0.1:8002/docs |
| `transcription` — WhisperX | http://127.0.0.1:8003/docs |
| `mock-mis` — тестовая МИС | http://127.0.0.1:8005/docs |
| `db` — PostgreSQL | Только внутренняя сеть Compose, порт на хост не опубликован. |

Порты приложения привязаны к `127.0.0.1`. Backend внутри Compose обращается к `transcription:8000`, `mock-mis:8000` и `db:5432`. Образ WhisperX настроен на CPU/int8.

### Подготовленная запись

Аудиозаписи, расшифровки конкретных консультаций, база данных и веса моделей **не включены в Git**. Свежий клон не содержит запись с локального демо-стенда. Без неё используйте «Пример приёма» или добавьте собственные вымышленные тестовые данные.

Для импорта подготовьте локальный каталог `demo-seed/` с аудио, расшифровкой и `manifest.json`:

```json
{
  "audio": "recording.m4a",
  "transcript": "prepared-transcript.json",
  "language": "ru",
  "title": "Тестовый приём"
}
```

Минимальный формат `prepared-transcript.json`:

```json
{
  "language": "ru",
  "segments": [
    {"text": "Учебная реплика пациента", "role": "patient", "start": 0, "end": 3}
  ]
}
```

После запуска базы и backend:

```bash
docker compose exec -T backend python -m app.import_demo /seed
docker compose exec -T backend python -m app.verify_mis
```

Первая команда сохраняет явно подготовленную запись и расшифровку в PostgreSQL, вторая проверяет отправку и чтение из тестовой МИС. Для подготовленного Windows-стенда `start-demo.cmd` собирает сервисы, импортирует запись и запускает проверку; без `demo-seed/manifest.json` этот скрипт не завершится успешно.

Обновить только интерфейс:

```bash
docker compose up -d --build --no-deps frontend
```

В Windows также доступен `update-frontend.cmd`. Затем нажмите Ctrl+F5 в браузере. `build-frontend.cmd` только собирает образ, без замены запущенного контейнера.

### Локальная разработка без контейнеров

Нужны Node.js **22.12+**, Python **3.12 или 3.13**. Пример PowerShell из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-dev.lock
npm --prefix frontend ci
$env:MEDHUB_DEMO_ENABLED = 'true'
$env:MEDHUB_PERSIST_WORKSPACES = 'false'
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8001 --workers 1
```

Во втором терминале:

```powershell
npm --prefix frontend run dev
```

Frontend: http://127.0.0.1:5173/. API: http://127.0.0.1:8001/docs. Vite проксирует `/api` на **8001**. В Bash используйте `.venv/bin/python` и `export` вместо синтаксиса PowerShell. Backend читает `.env` из корня; переменные окружения имеют приоритет.

Для полного сценария нужны отдельно запущенные PostgreSQL, тестовая МИС и распознаватель. При подключении к контейнерному `transcription` задайте `MEDHUB_WHISPERX_BASE_URL=http://127.0.0.1:8003`, `MEDHUB_WHISPERX_PROTOCOL=jobs` и `MEDHUB_WHISPERX_API_TOKEN`, равный `TRANSCRIPTION_API_KEY`. `speech_worker/` содержит альтернативный worker с другим протоколом; Compose использует `transcription/`.

## МИС и обработка данных

Тестовая МИС принимает 13 полей бланка через backend по `X-API-Key`. Ключ находится на сервере, в браузер не передаётся. Проверка и явное подтверждение текущей версии обязательны. Повторная отправка той же версии через API возвращает тот же документ; неверный ключ отклоняется. Для промышленной МИС нужна адаптация к API конкретного поставщика.

- **PostgreSQL:** хранит импортированную тестовую аудиозапись, расшифровку и документы тестовой МИС в постоянном volume `mis-demo-data`.
- **Рабочие сессии:** в Compose хранятся в памяти (`MEDHUB_PERSIST_WORKSPACES=false`), срок жизни — 24 часа; перезапуск backend их очищает. Процесс backend должен быть один.
- **Произвольные загрузки:** постоянное кеширование выключено (`MEDHUB_SPEECH_CACHE_ENABLED=false`). Это не означает отсутствия временных копий при обработке.
- **OpenAI:** при настроенном ключе текст разговора и история передаются внешнему сервису. Запрос использует `store: false`; это не гарантия полного отсутствия хранения на стороне провайдера.
- **Персональные данные:** полная автоматическая деперсонализация и производственная авторизация не реализованы. Используйте только вымышленные или заранее обезличенные данные. Интерфейс показывает настройки и условия обработки.
- `.env`, ключи, локальные записи, базы, модели и зависимости исключены из Git. Не публикуйте их вместе с проектом.

## Проверки

```powershell
npm --prefix frontend ci
npm --prefix frontend test
npm --prefix frontend run build
.\.venv\Scripts\python.exe -m pytest backend/tests -q
```

В ограниченной Windows-среде при ошибке загрузки конфигурации Vite можно использовать `--configLoader native`: `npm --prefix frontend test -- --configLoader native` и `npm --prefix frontend run build -- --configLoader native`.

Проверены **80 тестов frontend и 45 тестов backend**, TypeScript и production-сборка. На локальном контейнерном стенде отдельно проверены сохранённая расшифровка → OpenAI → бланк, экспорт DOCX и отправка/чтение из тестовой МИС. Это не подтверждает готовность нового распознавания в контейнере.

В существующем workflow `.github/workflows/backend.yml` остаются замечания Ruff; полный CI пока не проходит. Шаг проверки Compose также требует тестовых значений обязательных переменных окружения. Успешные функциональные тесты не означают полностью зелёный CI.

## Что готово

Реализованы три рабочие области, поиск по истории, редактирование реплик и бланка, анализ с проверяемыми источниками, Word по пользовательскому шаблону, тестовая МИС с отдельным API-ключом, PostgreSQL для демо и контейнеры.

### Известные ограничения

- Новый звук в текущем контейнерном стенде пока не распознаётся из-за ошибки загрузки модели. Подготовленная запись позволяет показывать последующие этапы независимо от неё.
- API предусматривает русский, казахский и автоопределение языка. Качество казахского и смешанной речи не подтверждено отдельным набором измерений; диаризация различает голоса, но не гарантирует роли врача и пациента.
- В подготовленной записи есть смешанные и неразборчивые реплики. Подтверждённые сведения заполняют часть бланка; остальные поля остаются пустыми до проверки врачом.
- Система не должна придумывать диагнозы и назначения. Автоматическое назначение дозировки по ИМТ не является готовой клинически проверенной функцией текущего интерфейса.
- Черновик вкладки не восстанавливается после перезагрузки. Перед закрытием скачайте Word или отправьте проверенные тестовые данные в тестовую МИС.
- DOCX сохраняет структуру и стили шаблона; окончательная постраничная вёрстка в Word/LibreOffice на этом стенде не проверена.
- Требуются исправление CI, промышленная авторизация, деперсонализация и подключение реальной МИС перед использованием с данными пациентов.
